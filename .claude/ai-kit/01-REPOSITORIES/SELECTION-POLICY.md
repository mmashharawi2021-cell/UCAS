# سياسة اختيار المستودعات

## معيار القرار
1. يجب إثبات الحاجة الفعلية في ملف وصف المشروع.
2. الأفضلية لحل أقل اعتماديات وتعقيدًا وبترخيص مناسب.
3. افحص: تاريخ تحديث حقيقي، إصدارات مدعومة، الترخيص، الإفصاح الأمني، التوثيق، التوافق، التكلفة الحقيقية، القدرة على التراجع.
4. لا تجمع بدائل من الفئة نفسها لمجرد توفرها (Goose/Cline، LangGraph/Mastra، إلخ).
5. قبل التثبيت سجل: الرابط، النسخة المحددة، hash أو lockfile، سبب الاعتماد، البديل المرفوض، تاريخ المراجعة، واسم المراجع.
6. لا تستخدم `curl | bash` أو تشغيل سكربتات منشورة دون مراجعة.
7. عند غياب معلومات حديثة، اكتب `لم يتم التحقق` ولا تدّع أن المشروع نشط أو آمن.

## قاعدة التقليل
- موقع ثابت: ربما لا يحتاج Supabase أو GIS أو أي Agent داخل الإنتاج.
- لوحة بيانات: PostgreSQL/Supabase حسب بيانات المشروع والخصوصية.
- GIS: MapLibre للعرض؛ PostGIS فقط عند الحاجة لاستعلام مكاني.
- إشعارات آنية: Realtime فقط إذا لزم، مع حدود التزامن والتكلفة.

## نتيجة الاختيار
وثّق جدولًا من: الحاجة -> المرشح -> لماذا -> تكلفة التشغيل -> مخاطره -> اختبارات القبول -> موافقة المستخدم.
