# UCAS 2.0 — خطة النشر والاسترجاع

هذه خطة تجهيز محلية، وليست إعلان نشر. كل commit وpush وفتح PR ودمج ونشر Release يحتاج موافقة المالك حسب طلبه. لا تتضمن الخطة أي تعديل تلقائي على Supabase الإنتاجي.

## نقطة الرجوع

- الفرع: `feat/companion-p1`.
- HEAD عند استلام العمل: `37f4dbe5c21a8f4366fefd5bc9afa8d61ed4f230`، مع تعديلات محلية غير محفوظة في commits.
- مرجع `main` المحلي للإصدار 1.7.0: `6447bc17508bd4315018a6cfcd4abe6434d7cefe`.
- حالة GitHub ونسخة الموقع المنشورة وإعداد Pages الفعلي تحتاج تحققًا وقت النشر؛ المراجع المحلية لا تثبت حالة الإنتاج.

## قبل الـ commits

1. إنهاء إصلاحات AI/PDF والمزامنة وشاشة التحميل المعتمدة ومراجعتها.
2. تشغيل `npm run check` و`npm run test:browser` و`npm run test:upgrade` على الحالة النهائية، وحفظ النتائج. على Windows يمكن استخدام `npm.cmd` و`CHROME_PATH` إلى Chrome المحلي.
3. التحقق من وحدة الإصدار 2.0.0، واكتمال ملفات الكاش، وعدم وجود تغييرات في `supabase/`، وعدم وجود بيانات خاصة ضمن الملفات المضافة.
4. إنشاء الإضافة باستخدام `npm run pack:companion`. الناتج `dist/UCAS_Moodle_Companion_0.5.0.zip` يبقى خارج git؛ يُرفق بالإصدار لاحقًا.
5. تجهيز دفعات مستقلة: AI/PDF، والمزامنة، والوثائق، وشاشة التحميل. الملفات المشتركة مثل `js/app.js` و`sw.js` و`package.json` والاختبارات تُقسَّم حسب التغيير، ولا تُضاف كاملة إلى أول دفعة دون مراجعة.

## خطوات النشر — بموافقة منفصلة على كل إجراء

1. **حفظ الـ commits محليًا:** بعد موافقة المالك، مع عرض معرفاتها وملفات كل دفعة. إعادة التحقق على المراجعة النهائية إذا تغير أي محتوى.
2. **رفع الفرع:** بعد موافقة منفصلة. رفع هذا الفرع وحده لا يشغّل سير العمل الحالي؛ `tests.yml` يعمل على PR إلى main، أو push إلى main، أو تشغيل يدوي.
3. **فتح PR إلى main:** بعد موافقة منفصلة. انتظار نجاح وظيفتي `test` و`browser` في `UCAS quality checks` على آخر مراجعة للـ PR؛ أي تعديل لاحق يلغي الاعتماد على النتائج القديمة.
4. **تحويل Pages:** بعد نجاح PR ومباشرة قبل الدمج المعتمد، يُغيَّر `Settings → Pages → Build and deployment → Source` إلى **GitHub Actions**. يسبق ذلك التحقق من الإعداد الحالي وتسجيل رابط الموقع والنسخة المنشورة، وحفظ نسخة احتياطية من بيانات الطالب خارج المستودع. الهدف ألا يتجاوز النشر القديم من الفرع بوابة الاختبارات الجديدة.
5. **الدمج:** بعد موافقة منفصلة. انتظار `UCAS quality checks` على commit الجديد في main، ثم `Deploy to GitHub Pages`. ملف `pages.yml` ينشر نفس SHA الذي اجتاز فحوص push إلى main. لا يُعلَن نجاح النشر قبل التحقق من SHA ورابط النشر والفتح الفعلي.
6. **التحقق بعد النشر:** فتح الموقع، والتحديث من نسخة قديمة، وإغلاقه وإعادة فتحه دون اتصال بعد اكتمال الكاش. التأكد من بقاء البيانات وفتح المساقات والملفات المحلية. تحديث الجهازين قبل تجربة المزامنة.
7. **GitHub Release:** بعد موافقة المالك على الخطوة، إنشاء الإصدار 2.0.0 وإرفاق ZIP الإضافة من نفس الشيفرة المعتمدة، ثم توثيق رابط التنزيل النهائي.
8. **تجربة المزامنة بحضور المالك:** اتباع `docs/testing/SYNC_TWO_DEVICES.md`. اختبارات Supabase الوهمية لا تثبت السياسات أو إعدادات الإنتاج. إذا ثبت غياب migration، تُجهَّز خطوة منفصلة بموافقة خاصة قبل تطبيقها.

## الرجوع عند ظهور مشكلة

- لا تمسح بيانات الموقع أو IndexedDB. احتفظ بالنسخة الاحتياطية السابقة للترقية وبنسخة حديثة خارج المستودع.
- لا تعكس دمج 2.0 كاملًا بصورة عمياء: مرجع 1.7 المحلي لا يحتوي سير نشر Pages الجديد، وإزالته بعد التحويل إلى Actions قد تمنع نشر الرجوع.
- جهّز فرع رجوع يعيد ملفات التشغيل إلى سلوك 1.7 من SHA أعلاه، مع إبقاء مسار CI/Pages وتثبيت رقم إصدار وكاش جديد ومتسق بواسطة `scripts/stamp-version.mjs`. رقم جديد ضروري لتحديث الأجهزة التي خزّنت 2.0.
- اختبر فرع الرجوع على ملف مستخدم تجريبي أنشأته 2.0، بما فيه بيانات الدراسة والملفات والعمل دون اتصال، قبل PR وموافقة ونشر الرجوع.
- كلا الإصدارين يستخدم schema 4، لكن ذلك وحده لا يثبت سلامة الرجوع. 1.7 لا يحتوي إصلاحات إعادة المحاولة والحذف المعلق للمزامنة؛ يجب تقييمها قبل إعادة تشغيل المزامنة على نسخة الرجوع.
- **نسخة ZIP بصيغة v2 لا تُستعاد في 1.7.** تبقى للاستعادة بواسطة نسخة تدعم 2.0. النسخة السابقة بصيغة JSON هي مسار الاستعادة القديم عند الحاجة، وقد لا تشمل تغييرات الطالب بعد أخذها.
- تحقق من اكتمال نشر الرجوع ونسخته الفعلية قبل إعلان التعافي. الرجوع إجراء منفصل يحتاج موافقة المالك.

## حدود التحقق

تجربة هاتف Android فعلي وSafari، والمزامنة الفعلية وسياسات Supabase، واستعادة الرجوع الكامل لم تُثبت بفحوص المتصفح المحلية وحدها. مراجعة A → B → A على نفس ملف المتصفح وملاحظات المزامنة الأخرى المؤجلة موثقة في `STATUS.md`.
