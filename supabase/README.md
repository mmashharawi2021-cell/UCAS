# Supabase backend (optional online features)

Used by **study groups** (chat), **push notifications while the app is closed**, **sync between the owner's devices** and the **AI lecture assistant**.
Everything else in the app works offline without it.

- Project: `xijpnqgaxvyigyrwcqmo` (region eu-central-1, free plan).
- Auth: **anonymous sign-in** (nickname only). Must stay enabled under
  Authentication → Sign In / Providers → "Allow anonymous sign-ins".
- Client settings: `js/cloud/config.js` (URL + publishable key — public by design; RLS protects data).

## What is stored

| Table | Contents | Who can read |
| --- | --- | --- |
| `profiles` | nickname | the user and people in the same groups |
| `groups` | name, optional course, invite code | members |
| `group_members` | membership + role | members of that group |
| `messages` | chat text (≤ 2000 chars) | members of that group |
| `push_subscriptions` | browser push endpoint + keys | the user |
| `scheduled_reminders` | reminder title + time (next 14 days) | the user |

Abuse limits: 20 messages/minute per user, 20 owned groups, 200 members per group, 300 pending reminders.

## Sync (email accounts)

- `sync_records` (one row per local record, last-write-wins by client `mtime`, pulled by server `updated_at`) and the private `sync-files` bucket (`<user id>/<resource id>`). Both require a non-anonymous user.
- Sign-in is an email magic link: set **Authentication → URL Configuration → Site URL** (and Redirect URLs) to the GitHub Pages address. The free plan's built-in email sender allows only a few emails per hour.

## AI assistant

- `functions/ai` (JWT checked in code). Secrets: `GEMINI_API_KEY` (Google AI Studio), `AI_ALLOWED_EMAILS` (comma-separated), optional `GEMINI_MODEL`, `AI_DAILY_LIMIT` (default 60).
- Only the selected lecture text (≤ 60k chars) is sent; usage is counted in `private.ai_usage`.

## Push

- `functions/push/index.ts` (deployed with JWT verification off; it authenticates callers with a random
  secret stored only in `private.push_config`).
- VAPID keys are generated by the function on first call and stored in `private.push_config`;
  the browser only gets the public key via `rpc('get_vapid_public_key')`.
- `pg_cron` job `push-reminders` calls the function every minute; a trigger on `messages` calls it for each new message.

## Re-deploying to another project

1. Apply `migrations/*.sql` in order (edit the function URL in `20261028200654_push_infrastructure.sql`).
2. Deploy `functions/push` with `verify_jwt = false`.
3. Enable anonymous sign-ins.
4. Call `select private.call_push('{"type":"init"}');` once to create the VAPID keys.
5. Update `js/cloud/config.js` and the CSP `connect-src` in `index.html`.
